# Реестр решений — Agent Bureau Office

Этот файл хранит не ход внутренних рассуждений агентов, а проверяемые решения:
что выбрано, зачем, какие альтернативы отклонены и когда решение пересмотреть.

## ADR-001 — Local-first live telemetry

- **Статус:** принято, дополнено ADR-011
- **Дата:** 2026-07-31
- **Решение:** первая версия работает полностью локально на `127.0.0.1`.
- **Почему:** живые агенты находятся на компьютере пользователя; локальный путь
  быстрее, приватнее и не требует аккаунта, облачной базы или входящего доступа
  к Mac.
- **Отклонённая альтернатива:** передавать живую локальную телеметрию напрямую на
  Vercel без отдельного relay и модели доступа.
- **Цена решения:** публичный сайт показывает demo, а живую смену видно только
  рядом с запущенным локальным collector.
- **Пересмотреть, когда:** понадобится просмотр с телефона или нескольких машин.

## ADR-002 — Визуализация является read-only observer

- **Статус:** принято
- **Решение:** Pixel Office не может запускать, останавливать, одобрять или
  продолжать работу агентов.
- **Почему:** сбой красивого интерфейса не должен влиять на агентский цикл и не
  должен создавать новый источник бесконечных повторов.
- **Последствие:** управление агентами остаётся у оркестратора и Codex.
- **Пересмотреть, когда:** появится отдельная модель разрешений и явные
  подтверждения пользователя для управляющих действий.

## ADR-003 — Собственный нормализованный поток событий

- **Статус:** принято
- **Решение:** UI читает единое состояние collector, а не transcript и не
  внутренние файлы Codex.
- **Источники:** Codex Hooks и будущие события `bureauctl`.
- **Почему:** transcript не является стабильным API; собственная схема позволяет
  менять источник телеметрии без переделки интерфейса.
- **Хранение:** `.bureau/events.jsonl` как append-only журнал и
  `.bureau/state.json` как текущий снимок.
- **Пересмотреть, когда:** Bureau начнёт владеть App Server-сессией и потребуется
  более подробный thread/turn/item stream.

## ADR-004 — Передавать только allowlist безопасных полей

- **Статус:** принято
- **Решение:** collector принимает роль, задачу, статус, модель, effort, фазу,
  короткое резюме и verdict проверки.
- **Не передавать:** промпты, ответы, transcript, tool input/output, diff,
  содержимое файлов, абсолютные пути и секреты.
- **Почему:** для пиксельной сцены достаточно операционного статуса; сырые данные
  увеличивают риск утечки и не улучшают наблюдение.
- **Примечание:** интерфейс показывает объяснение решения, подготовленное агентом,
  но не скрытую chain-of-thought.

## ADR-005 — Hooks не участвуют в принятии решений

- **Статус:** принято
- **Решение:** telemetry hook всегда advisory; он не возвращает `deny`, `block`
  или `continue: false`.
- **Почему:** observer не должен менять approval flow или повторно запускать
  завершившийся агентский цикл.
- **Проверка:** `Stop` и `SubagentStop` возвращают нейтральное
  `{"continue":true}`; остальные события завершаются с пустым stdout.

## ADR-006 — Пиксельная сцена поверх обычного DOM/CSS

- **Статус:** заменено ADR-010
- **Историческое решение:** первая сцена была полностью собрана на React и CSS
  без игрового движка.
- **Почему заменено:** CSS-персонажи и комнаты оказались приблизительной
  стилизацией и визуально разошлись с уже утверждённой pixel-art сценой.
- **Что осталось в силе:** доступность, адаптивность и интерактивность по-прежнему
  реализуются обычным DOM/CSS; collector остаётся отделённым от отрисовки.

## ADR-007 — Researcher работает через отдельный Cursor adapter

- **Статус:** принято
- **Дата:** 2026-07-31
- **Решение:** внешние исследования выполняет профиль
  `Cursor Grok 4.5 High Fast` в Ask mode через Cursor Agent CLI.
- **Почему:** обычный пул субагентов Codex не предоставляет Grok; отдельный adapter
  позволяет использовать подписку Cursor и наблюдать фактическую модель.
- **Защита:** adapter выбирает canonical slug, содержащий `grok-4.5`, `high`, `fast`,
  и сверяет нормализованное поле `model` стартового `stream-json` события с display
  name или canonical slug этой записи. При несовпадении задача блокируется без тихой
  замены.
- **Изоляция:** Cursor запускается в отдельной пустой workspace с sandbox; корень
  пользовательского проекта не помечается trusted и не передаётся Researcher.
- **Цена решения:** нужен установленный и авторизованный Cursor Agent CLI; Fast-вариант
  расходует лимиты быстрее стандартного.
- **Отклонённая альтернатива:** считать `service_tier: priority` прямого xAI API тем
  же режимом, что Cursor Fast.
- **Пересмотреть, когда:** Cursor изменит slug, CLI-контракт или появится нативный
  provider adapter в оркестраторе.

## ADR-008 — Ограниченные циклы исполнения и проверки

- **Статус:** принято
- **Дата:** 2026-07-31
- **Решение:** после первой сдачи разрешено не более двух раундов доработки.
- **Почему:** верификатор не должен превращать исправимую задачу в бесконечный цикл.
- **Правило:** каждое замечание имеет критерий, доказательство, `issue_id` и условие
  закрытия; прежнее замечание нельзя повторить без нового доказательства.
- **После лимита:** оркестратор принимает с риском, сужает задачу, меняет
  исполнителя/модель либо эскалирует выбор пользователю.

## ADR-009 — Markdown является источником истины для будущего RAG

- **Статус:** принято
- **Дата:** 2026-07-31
- **Решение:** контекст, ADR, lessons и research reports хранятся в Markdown; RAG
  позже индексирует эти документы и возвращает ссылки на оригинал.
- **Почему:** файлы остаются читаемыми, переносимыми и пригодными для Git даже без
  векторной базы.
- **Не хранить:** скрытые рассуждения моделей. Сохранять решения, краткое обоснование,
  доказательства, последствия и условия пересмотра.
- **Пересмотреть, когда:** полнотекстовый поиск перестанет находить релевантные
  перефразированные решения.

## ADR-010 — `public/og.png` является канонической сценой офиса

- **Статус:** заменено ADR-013 в части render path; сохранено как style reference
- **Дата:** 2026-07-31
- **Решение:** точный файл `public/og.png` используется как неизменяемая
  визуальная основа Pixel Office. Иерархия, доступные hotspot-кнопки, подписи
  агентов, маршруты и пакеты задач, статусы выбора и карточка назначения
  добавляются только отдельным DOM/CSS overlay поверх изображения.
- **Почему:** пользователь утвердил именно эту композицию, персонажей, свет,
  палитру и pixel-art характер. Повторная отрисовка приблизительными CSS-формами
  потеряла различия между агентами и нарушила визуальную преемственность.
- **Отклонённая альтернатива:** заново собрать похожие комнаты и универсальных
  роботов CSS-спрайтами.
- **Ограничение overlay:** интерактивный слой может объяснять состояние и передачу
  задачи, но не должен перерисовывать, закрывать или подменять персонажей сцены.
- **Последствие:** координаты hotspot и линий привязаны к соотношению сторон
  исходного изображения `1672 × 941`; адаптивность сохраняет это соотношение либо
  использует горизонтальный скролл сцены.
- **Пересмотреть, когда:** пользователь явно утвердит новый исходник сцены или
  попросит изменить саму иллюстрацию.

## ADR-011 — Публичный Vercel-сайт является demo-зеркалом

- **Статус:** принято
- **Дата:** 2026-07-31
- **Решение:** исходный код публикуется в public GitHub repository, а Next.js UI —
  на Vercel. Облачная версия использует встроенный demo snapshot; локальная версия
  продолжает читать живые события с `127.0.0.1:7331`.
- **Production URL:** `https://agent-bureau.vercel.app`.
- **Почему:** пользователь получает постоянную ссылку на визуальный эксперимент,
  не открывая входящий доступ к своему компьютеру и не публикуя локальную
  телеметрию.
- **Безопасность:** `.bureau`, `.env`, `.vercel`, build outputs и локальный package
  cache исключены из Git. Публичный UI не проксирует collector.
- **Сборка:** `vinext build` остаётся проверкой local/Sites runtime, а
  `vercel.json` явно задаёт `next build` для Vercel.
- **Пересмотреть, когда:** понадобится авторизованное outbound-only облачное
  зеркало живых событий.

## ADR-012 — Art-first viewport и постоянный roster

- **Статус:** принято, визуальный слой дополнен ADR-013
- **Дата:** 2026-07-31
- **Решение:** первый экран является самой канонической сценой `public/og.png`,
  вписанной целиком в viewport. Служебный HUD и пул агентов компактно плавают
  поверх, а подробности выбранного назначения открываются в закрываемой панели,
  которая не меняет размеры сцены.
- **Иерархия:** оркестратор занимает фиксированный верхний слот; исполнители —
  четыре функциональных слота. SVG-маршруты и кликабельные пакеты показывают
  направление передачи задачи.
- **Live-модель:** встроенный demo roster задаёт постоянный состав. Live snapshot
  обновляет совпавшие записи по `id` или нормализованной роли. Не совпавшие
  участники roster остаются `standby`; дополнительные live-агенты добавляются в
  пул, но не вытесняют канонические места.
- **Почему:** состояние collector неполно по определению: отсутствие события не
  означает исчезновение роли. Одновременно визуальный референс должен оставаться
  главным объектом, а телеметрия — объясняющим слоем.
- **Отклонённые альтернативы:** заменять roster каждым snapshot; постоянно
  резервировать колонку под инспектор; обрезать сцену на узком viewport.
- **Проверка:** snapshot с одним Researcher сохраняет восемь участников и сообщает
  `1 live · 7 standby`; карточка открывается только после выбора агента/пакета.

## ADR-013 — Отделить интерьер от анимируемых агентов

- **Статус:** принято, планировка заменена ADR-014
- **Дата:** 2026-07-31
- **Решение:** `public/og.png` остаётся каноническим style reference и social image,
  но рабочая сцена собирается из двух независимых слоёв: пустого интерьера
  `public/office-empty-v2.png` и отдельных ролевых PNG-спрайтов из
  `public/agents/`. Каждый агент является DOM-кнопкой со своим sprite layer,
  статусной анимацией, подписью и доступной карточкой задачи.
- **Причина:** монолитная иллюстрация точно воспроизводила референс, но не могла
  показать появление нового агента, смену состояния или расширение пула без
  повторной генерации всей сцены.
- **Масштабирование:** каждый агент имеет стабильный DOM identity; незнакомая роль
  получает детерминированный fallback-спрайт, поэтому новый `agentId` не ломает
  render. Правила размещения уточнены в ADR-014.
- **Анимации:** новый DOM-узел входит через `agent-arrive`; `planning`, `working`,
  `reviewing`, `revision`, `blocked`, `done` и `idle` имеют разные CSS keyframes;
  `prefers-reduced-motion` отключает непрерывное движение.
- **Инварианты:** интерьер, заголовок, палитра, освещение и pixel-art характер
  сохраняют утверждённый референс; универсальные CSS-роботы не используются.
- **Проверка:** в demo отображаются восемь различимых спрайтов, а live snapshot с
  одним Researcher показывает `1 live · 7 standby`; вычисленные стили спрайтов
  содержат соответствующие status animation names.

## ADR-014 — Восемь ролей получают восемь персональных кабинетов

- **Статус:** принято
- **Дата:** 2026-07-31
- **Решение:** рабочий фон `public/office-departments-v3.png` содержит ровно восемь
  пустых, визуально разделённых рабочих зон. `STAGE_SLOTS` закрепляет постоянную
  роль за её кабинетом, а не размещает overflow-спрайты между чужими столами.
- **Верхний уровень:** архив Researcher; увеличенный центральный command room
  Оркестратора; QA-лаборатория Верификатора.
- **Нижний уровень:** слева направо кабинеты Кодера, Дизайнера, Копирайтера,
  Маркетолога и Иллюстратора. Мебель, освещение и реквизит каждого помещения
  кодируют функцию роли без вшитых текстовых подписей.
- **Иерархия:** кабинет Оркестратора выше и заметно крупнее. SVG-маршруты выходят
  из него ко всем семи исполнителям.
- **Расширение пула:** неизвестные или дублирующиеся live-роли не ставятся в
  проходе. Они остаются кликабельными в нижнем пуле и счётчике «цифровой аннекс»;
  карточка задачи доступна оттуда. Новый физический кабинет требует явного
  расширения планировки, чтобы оставаться действительно кастомным.
- **Отклонённая альтернатива:** универсальные hot desk-точки поверх существующей
  мебели — они визуально превращали часть агентов в стоящих между рабочими местами.
- **Проверка:** demo roster показывает восемь спрайтов, каждый внутри отдельной
  комнаты; ни один постоянный агент не входит в `stage.overflow`.
