# Уроки проекта — Agent Bureau Office

Здесь фиксируются повторяемые ошибки и проверяемые правила, которые помогают не
наступать на те же грабли. Это не журнал скрытых рассуждений: каждый урок содержит
наблюдаемый симптом, принятое правило и способ проверки.

## LESSON-001 — Не подменять утверждённую визуальную сцену приближением

- **Дата:** 2026-07-31
- **Симптом:** вместо утверждённой pixel-art иллюстрации интерфейс показал заново
  собранные CSS-комнаты и похожих друг на друга роботов; результат воспринимался
  как другой, заметно более слабый дизайн.
- **Причина:** референс был использован как общее стилевое направление, хотя уже
  являлся утверждённым визуальным результатом.
- **Правило:** если визуальная сцена или арт явно одобрены, использовать точный
  asset как каноническую основу. Не заменять его приблизительной CSS-, SVG- или
  повторно сгенерированной стилизацией без отдельного явного решения пользователя.
- **Допустимое изменение:** поверх канонического asset можно добавлять независимые
  интерактивные слои, если они не меняют и не закрывают ключевой арт.
- **Проверка перед сдачей:** канонический файл присутствует в финальном render path;
  персонажи и интерьер не дублируются самодельными спрайтами; любое отступление
  подтверждено новой записью ADR или прямым запросом пользователя.
- **Связанное решение:** ADR-010.

## LESSON-002 — Live snapshot не должен стирать состав офиса

- **Дата:** 2026-07-31
- **Симптом:** после единственного события Researcher интерфейс показывал только
  Researcher; оркестратор и остальные специалисты исчезали, хотя они являются
  постоянным составом бюро.
- **Причина:** live snapshot целиком заменял demo roster вместо обновления
  присутствия и статусов совпавших агентов.
- **Правило:** live-телеметрия обогащает постоянный roster. Совпадение выполняется
  сначала по `id`, затем по нормализованной роли. Агент без свежего live-события
  остаётся видимым со статусом `standby`, без выдуманной активной задачи.
- **Проверка перед сдачей:** при snapshot из одного Researcher UI показывает
  `1 live · 5 standby`, все шесть участников доступны в пуле, а оркестратор
  сохраняет своё место в иерархии.
- **Связанное решение:** ADR-012.
