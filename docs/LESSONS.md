# Уроки проекта — Agent Bureau Office

Здесь фиксируются повторяемые ошибки и проверяемые правила, которые помогают не
наступать на те же грабли. Это не журнал скрытых рассуждений: каждый урок содержит
наблюдаемый симптом, принятое правило и способ проверки.

## LESSON-001 — Не подменять утверждённую визуальную сцену приближением

- **Дата:** 2026-07-31
- **Симптом:** вместо утверждённой pixel-art иллюстрации интерфейс показал заново
  собранные CSS-комнаты и похожих друг на друга роботов; результат воспринимался
  как другой, заметно более слабый дизайн.
- **Причина:** референс был использован как общее стилевое направление, хотя уже
  являлся утверждённым визуальным результатом.
- **Правило:** если визуальная сцена или арт явно одобрены, использовать точный
  asset как каноническую основу. Не заменять его приблизительной CSS-, SVG- или
  повторно сгенерированной стилизацией без отдельного явного решения пользователя.
- **Допустимое изменение:** поверх канонического asset можно добавлять независимые
  интерактивные слои, если они не меняют и не закрывают ключевой арт.
- **Проверка перед сдачей:** канонический файл присутствует в финальном render path;
  персонажи и интерьер не дублируются самодельными спрайтами; любое отступление
  подтверждено новой записью ADR или прямым запросом пользователя.
- **Связанное решение:** ADR-010.

## LESSON-002 — Live snapshot не должен стирать состав офиса

- **Дата:** 2026-07-31
- **Симптом:** после единственного события Researcher интерфейс показывал только
  Researcher; оркестратор и остальные специалисты исчезали, хотя они являются
  постоянным составом бюро.
- **Причина:** live snapshot целиком заменял demo roster вместо обновления
  присутствия и статусов совпавших агентов.
- **Правило:** live-телеметрия обогащает постоянный roster. Совпадение выполняется
  сначала по `id`, затем по нормализованной роли. Агент без свежего live-события
  остаётся видимым со статусом `standby`, без выдуманной активной задачи.
- **Проверка перед сдачей:** при snapshot из одного Researcher UI показывает
  `1 live · 7 standby`, все восемь участников доступны в пуле, а оркестратор
  сохраняет своё место в иерархии.
- **Связанное решение:** ADR-012.

## LESSON-003 — Утверждённый арт не равен рабочей модели сцены

- **Дата:** 2026-07-31
- **Симптом:** точный референс выглядел правильно, но агенты оставались пикселями
  одного изображения: их нельзя было независимо анимировать, добавлять и
  пересаживать между рабочими местами.
- **Причина:** визуальный референс одновременно использовался как интерьер,
  персонажи и состояние приложения.
- **Правило:** для живой визуализации разделять неизменяемое окружение и сущности.
  Интерьер может быть raster asset, но каждый агент должен иметь собственный
  стабильный DOM identity, sprite, статус, координаты и lifecycle-анимацию.
- **Проверка перед сдачей:** новый агент появляется без изменения background asset;
  переполнение остаётся в аннексе/пуле; смена статуса меняет animation name;
  reduced motion сохраняет читаемость без движения.
- **Связанное решение:** ADR-013.

## LESSON-004 — Отдельный спрайт ещё не означает персональное рабочее место

- **Дата:** 2026-07-31
- **Симптом:** агенты стали анимируемыми DOM-сущностями, но дополнительные роли
  оказались между кабинетами и выглядели как временно поставленные в проходе.
- **Причина:** модель сущностей была масштабируемой, а планировка осталась
  рассчитанной на пять исходных персонажей.
- **Правило:** постоянная роль получает не только sprite и координату, но и
  семантически подходящее помещение с собственной мебелью, светом и реквизитом.
  Нельзя маскировать отсутствие комнаты универсальной точкой поверх чужого стола.
- **Проверка перед сдачей:** восемь постоянных ролей занимают восемь визуально
  отделённых кабинетов; overflow не рендерится поверх здания и доступен в аннексе.
- **Связанное решение:** ADR-014.

## LESSON-005 — Расширяемый пул должен быть конфигурацией, а не правкой сцены

- **Дата:** 2026-07-31
- **Симптом:** каждый новый специалист потенциально требовал добавлять роль,
  координаты, разметку и новый фон вручную.
- **Причина:** визуальные сущности были динамическими, но каталог рабочих мест и
  процесс создания профиля оставались частью исходного кода.
- **Правило:** отделять профиль агента от runtime-состояния. Кабинет, аватар и
  system prompt выбираются из data-driven каталога; наблюдаемое состояние не
  содержит секретный prompt и честно сообщает, подключён ли runtime.
- **Проверка перед сдачей:** новый профиль создаётся из UI, переживает перезагрузку,
  не занимает чужой физический слот и удаляется без изменения проекта. Exact ID
  постоянного roster проверяется раньше совпадения роли; malformed и duplicate
  localStorage-записи покрыты отдельными поведенческими тестами.
- **Связанное решение:** ADR-015.

## LESSON-006 — Выбор runtime не равен факту запуска

- **Дата:** 2026-07-31
- **Симптом:** карточка с выбранными provider и model могла выглядеть как
  подтверждение, что агент уже работает именно на этой модели.
- **Причина:** конфигурация пользователя и наблюдаемая телеметрия пытались
  использовать одни поля без явной границы доверия.
- **Правило:** requested runtime хранится в профиле, actual runtime приходит
  только от локального адаптера после preflight/старта. UI подписывает профиль
  как `CONFIG ONLY` и не выполняет endpoint или shell-команды из JSON.
- **Безопасность:** хранить имя env-переменной, а не API-ключ; отклонять URL с
  credentials/query/hash и публичные client-side env-префиксы. Недоверенный
  custom adapter нельзя автоматически запускать только потому, что он добавлен
  в каталог.
- **Проверка перед сдачей:** произвольные model/reasoning проходят; небезопасные
  endpoint/env отбрасываются; reload сохраняет профиль; карточка фактической
  работы обновляется только live-событием.
- **Связанное решение:** ADR-016.
